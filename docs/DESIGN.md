# 디자인 시스템 — 어두운 바탕, 보라 한 겹, 형광 한 점

모든 서비스에 같은 얼굴을 주기 위한 문서. 새 프로젝트를 시작할 때 §3의 토큰 블록을 복사해서 시작하고, 판단이 갈릴 때는 §1의 원칙으로 돌아온다.

> **2026-08-27 개정.** 기본값을 **라이트에서 다시 다크로** 뒤집고, 그 사이에 **보라 한 겹(`#6332EB`)을 새로 넣었다.** 형광 한 점 규칙(§2)과 말투(§9)는 그대로다. 왜 두 번 뒤집었는지는 §1 끝에 적어뒀다 — **그 이력을 읽지 않고 색만 가져가면 세 번째로 뒤집게 된다.**

---

## 1. 무드 — 왜 이렇게 생겼나

세 개의 축이 있다.

**밥 아저씨 (Bob Ross)**
> "참 쉽죠?" · "실수란 없어요. 그저 행복한 사고죠."

차분하고, 따뜻하고, 절대 다그치지 않는다. **어려운 것을 쉬워 보이게** 만든다. 사용자가 뭘 잘못해도 세상은 안 무너진다.

**Tally 같은 여백**
정보를 채우지 않고 **덜어낸다.** 한 화면에 한 가지 이야기, 한 개의 액션. 큰 글씨, 넉넉한 여백, 둥근 면. 화려해서 좋아 보이는 게 아니라 **숨 쉴 틈이 있어서** 좋아 보인다.

**세 겹의 색 — 60 / 30 / 10**

| 비중 | 색 | 이름 | 무엇을 맡나 |
| --- | --- | --- | --- |
| **60%** | `#121019` | Deep Violet Slate | 깊은 생각과 내면. 화면의 바탕이고, 나머지 둘이 서는 자리다 |
| **30%** | `#6332EB` | Electric Purple | AX, 생각의 틀. 카드뉴스 트레이·메인 프레임·뱃지 — **면(面)으로만** |
| **10%** | `#8FFF00` | Neon Lime | 용기, 동기부여, 생각소스. 3초 후킹 단어·실행 버튼·커서 |

이 비율은 **면적의 목표가 아니라 순서**다. 어느 색도 자기 위 단계보다 넓어지지 않는다. 특히 **10%는 상한이지 채워야 할 칸이 아니다** — 실제 랜딩에서 형광이 덮는 면적은 1~2%고, 그게 맞다 (§2).

### 한 문장으로

> **어둠 위에 보라로 틀을 세우고, 붓끝의 한 점만 형광으로.**

어두운 바탕은 "여기 뭔가 쌓여 있다"를 만들고, 보라 한 겹은 그것을 **읽을 수 있는 형태**로 묶고, 형광 한 점은 "여기서 시작한다"를 만든다. 셋 다 필요하다.

### 두 번 뒤집은 이력 — 여기가 이 문서에서 제일 중요한 문단이다

**1차 — 다크에서 라이트로.** 처음엔 다크 베이스였다. 형광 초록이 어두운 바탕에서 가장 예쁘게 터지니까 자연스러운 선택처럼 보였다. 그런데 **어두운 바탕 + 형광, 딱 두 겹이면 사이버펑크**로 읽힌다. 밥 아저씨 축이 완전히 죽고 "개발자가 만든 개발자용 도구" 냄새가 났다. 그래서 흰 종이로 뒤집었다.

**2차 — 라이트에서 다시 다크로.** 채널의 정체성이 *"만드는 사람"*에서 ***"AX하는 창업가"***로 옮겨갔다. 흰 종이는 "누구나 열어보면 된다"에는 맞았지만, 이 채널이 이제 쌓는 것 — 생각·AX·조직 — 을 담기엔 너무 가볍다.

**같은 실수를 반복하는 게 아니다.** 1차의 진단이 *"다크가 틀렸다"*가 아니었기 때문이다. 진단은 **"두 겹이 틀렸다"**였다. 검정과 형광 사이에 아무것도 없으면 형광이 화면의 유일한 정보가 되고, 그러면 네온사인이 된다.

이번엔 그 사이에 **보라 한 겹이 들어간다.** 카드가 트레이 위에 놓이고, 뱃지가 자기 면을 갖고, 프레임이 생긴다. 형광은 더 이상 유일한 색이 아니라 **셋 중 마지막**이다.

⚠️ **그래서 보라를 빼고 이 팔레트를 쓰면 정확히 1차의 실패로 돌아간다.** `#121019` + `#8FFF00` 두 개만 가져가는 건 이 시스템이 아니다. 보라가 30%를 실제로 채우고 있는지가 이 개정이 성공했는지의 유일한 판정 기준이다.

**라이트는 버리지 않았다.** 다만 이제 *기본*이 아니라 *대응*이다 (§3).

## 2. 형광 예산 — 이 시스템의 전부

> ### 한 화면에 형광 초록은 딱 한 곳.
> 나머지는 전부 보라 기운의 중립색 (§3).

새 화면을 만들 때 스스로에게 묻는다: **"이 화면에서 형광이 찍힐 그 한 점은 어디인가?"** 보통 그 화면의 주인공 액션 하나다. 정하고, 나머지는 다 중립으로 눕힌다.

이 규칙은 **말은 쉽고 지키기는 어렵다.** "강조 색"이라고 생각하는 순간 버튼·칩·라디오·슬라이더·링크밑줄·로고에 하나씩 붙어서, 정신 차리면 화면에 형광이 8개다. 그러면 **눈이 아프다.** 그래서 예산을 숫자로 못 박는다.

| | |
| --- | --- |
| ✅ **형광 1개** | 그 화면의 주인공 액션 (Primary 버튼 / 지금 주목할 대상) |
| ✅ 예외: 브랜드 마크 | 정체성이다. 작고 늘 같은 자리에 고정이라 주목을 다투지 않는다 (§7). 글로우만 금지 |
| ✅ 예외: 작은 상태 점 | ~8px 인디케이터. 정보를 전달하고 면적이 없다 |
| ✅ 예외: 포커스 링 | 키보드로 눌렀을 때만 잠깐 나타난다 (접근성) |
| ❌ 선택된 칩 · 라디오 · 체크박스 · 슬라이더 | `accent-color`에 무심코 넣게 되는 최대 함정. 중립으로 |
| ❌ 링크 밑줄 · 구분선 · 가이드선 | 조용한 참고물이다. 중립으로 |

**고정된 것 vs 흩어진 것.** 로고처럼 *늘 같은 자리에 고정된* 형광은 눈이 곧 배경으로 처리해서 피로하지 않다. 진짜 피로는 *여기저기 흩어진* 형광(선택된 칩, 슬라이더 손잡이, 밑줄…)에서 온다 — 시선이 매번 "저건 뭐지?" 하고 붙잡히기 때문. 그래서 예산은 **개수**가 아니라 **흩어짐**을 센다.

### 보라 면은 예산에 안 들어간다 (중요)

다크로 뒤집으면서 **파스텔 틴트 면(`--paper-*`)이 통째로 빠지고 보라 한 겹(`--iris`)이 그 자리를 물려받았다.** 흰 종이 위의 "색깔 있는 종이"가 어두운 바탕 위의 "떠 있는 트레이"가 된 것이다. 색은 바뀌었지만 **규칙은 글자 그대로 옮겨온다** — 이건 형광 예산과 **별개**이고, 조건이 붙는다.

| | |
| --- | --- |
| ✅ **면(배경)으로만** | 카드 트레이·메인 프레임·뱃지·섹션 블록의 배경 |
| ✅ 층은 두 겹까지 | 트레이 안에 또 트레이를 넣지 않는다. 세 겹이 되면 어디가 바탕인지 사라진다 |
| ❌ 글자 · 아이콘 · 얇은 선 | `#6332EB`는 `#121019` 위에서 **2.86:1**이다 (§3). 본문은커녕 큰 글씨 기준(3:1)도 못 넘는다 |
| ❌ 채도·밝기 올려서 형광처럼 쓰기 | 보라가 튀기 시작하면 형광이 설 자리가 없어진다. 그 순간 §1 의 60/30/10 이 뒤집힌다 |

**판별법은 그대로다.** 그 색을 흑백으로 바꿨을 때 레이아웃이 그대로면 면이다. 뭔가 안 읽히면 그건 강조색이었던 거고, 규칙 위반이다.

⚠️ **보라가 글자여야 할 때는 `--iris-soft`(7.08:1)를 쓴다.** `--iris` 자체를 밝히지 않는다 — 밝히는 순간 트레이 색이 화면마다 달라지고, 서비스끼리 얼굴이 갈린다. 이건 `--acid` 와 `--acid-deep` 을 나눠 둔 것과 정확히 같은 구조다 (§3).

### 일러스트가 여러 장 깔릴 때 (카드 그리드)

서비스 카드마다 일러스트가 있고 그 안에 각각 형광이 한 점씩 있으면, 그리드 한 화면에 형광이 여섯 개가 된다. 예산 위반처럼 보이지만 아니다 — §2가 세는 건 개수가 아니라 **흩어짐**이고, 격자 위에 규칙적으로 놓인 점은 로고처럼 **고정 패턴**으로 읽힌다. 눈이 "저건 뭐지?" 하고 매번 붙잡히지 않는다.

**단, 조건이 붙는다.**

- 일러스트 **한 장 안에는 형광이 정확히 하나.** 두 개가 되는 순간 그 카드 안에서 시선이 갈라진다.
- **카드 밖 UI에는 형광을 하나도 더 두지 않는다.** 선택된 칩, featured 표시 점, 태그, 링크 — 전부 중립. 격자 밖으로 새는 형광 하나가 패턴을 깨고 화면을 어지럽게 만든다.
- 히어로의 Primary 버튼은 이 격자 **바깥의 한 점**이라 따로 계산한다. 그래서 랜딩에는 형광이 "버튼 1 + 격자 패턴" 두 층으로만 존재한다.

*"카드마다 대표작이라고 초록 표시를 하나씩 찍고 싶다"는 유혹이 여기서 온다. 찍지 마라 — 그 점들은 격자에 안 맞아서 진짜로 흩어진다. 대표작은 이미 '목록 맨 앞'이라는 형태로 드러나 있다.*

### 글로우(halo) 금지 — 화면에서는

```css
box-shadow: 0 0 24px rgba(143, 255, 0, 0.3); /* ❌ 절대 */
text-shadow: 0 0 26px rgba(143, 255, 0, 0.4); /* ❌ 절대 */
```

**형광색에 글로우를 씌우면 눈이 찔린다.** `#8FFF00`은 어두운 바탕에서 **14.79:1**이라 이미 **색 하나로 튄다.** 빛나 보이게 하고 싶은 유혹이 들면, 글로우 대신 **주변을 더 조용하게** 만든다.

⚠️ **다크로 오면서 이 유혹이 몇 배가 됐다.** 어두운 바탕에서 글로우는 실제로 예뻐 보이고, 그래서 하나씩 붙다가 화면이 네온사인이 된다 — §1 이 적어둔 1차 실패의 경로가 정확히 이것이다. 라이트일 때는 글로우가 애초에 안 예뻐서 저절로 지켜지던 규칙이라, **이제부터는 의식적으로 세야 한다.**

**예외는 하나 — 키비주얼.** 로고 렌더·인스타 카드뉴스 표지처럼 **한 장짜리 그림**에는 글로우를 쓴다 (`public/brand/source/` 의 렌더가 그렇다). 그건 UI 가 아니라 포스터이고, 그 위에 누를 것도 읽을 것도 없다.

**그 글로우를 마크 파일이나 화면으로 가져오지 않는다.** 마크 SVG(§7)에는 글로우가 0개고, 그래서 16px 에서도 뭉개지지 않는다.

## 3. 색

### 먼저 알아야 할 사실: 이제 **보라**가 '글자색이 아니다'

라이트 시절 이 자리에는 "`#8FFF00`은 글자색이 아니다"가 있었다. 다크로 뒤집으면서 **그 문제는 형광에서 보라로 옮겨갔다.** 측정값이 규칙을 정한다.

| 조합 | 대비 | 판정 |
| --- | --- | --- |
| `#8FFF00` 글자 / `#121019` 바탕 | **14.79 : 1** | ✅ 다크에서 형광은 **글자로도 된다** |
| `#6332EB` 글자 / `#121019` 바탕 | **2.86 : 1** | ❌ 본문은 물론 큰 글씨(3:1)도 못 넘는다. **면 전용** |
| `#A98CFF` 글자 / `#121019` 바탕 | **7.08 : 1** | ✅ 보라를 글자로 써야 할 때는 이것 (`--iris-soft`) |
| 흰 글자 / `#6332EB` 면 | **6.59 : 1** | ✅ 뱃지·트레이 안 글자 |
| `#14140F` 글자 / `#6332EB` 면 | **2.80 : 1** | ❌ **가장 흔한 실수** — 아래 표 참고 |
| 검정 글자 / `#8FFF00` 면 | **14.49 : 1** | ✅ 버튼에 최적 |
| `#8FFF00` 글자 / 흰 바탕 | 1.27 : 1 | ❌ 라이트 대응에서는 여전히 금지. `--acid-deep`(6.36:1) |

> ⚠️ **형광 위 글자는 어둡게, 보라 위 글자는 밝게.** 두 개가 정반대라 한쪽 습관이 다른 쪽을 망친다. 그래서 토큰을 `--on-acid` 와 `--on-iris` 로 따로 뒀다 — 직접 색을 쓰지 말고 이 둘만 쓴다.

### 토큰 (복붙용)

```css
:root {
  color-scheme: dark;

  /* ── 60% 바탕 — Deep Violet Slate ────────
     보라 기운이지 파란 기운이 아니다. 판별은 R 과 G 로 한다 (아래 '중립색' 참고). */
  --bg: #121019;
  --surface: #1a1725;       /* 카드 면. 바탕 위에서 아주 살짝 뜬다 */
  --surface-2: #221e30;     /* 인풋 안쪽, 비활성 면 */
  --line: #2a2539;          /* 기본 구분선 */
  --line-strong: #3b3550;   /* 인풋 테두리처럼 형태를 잡아야 하는 선 */
  --ink: #edebf5;           /* 본문 — 15.98:1 */
  --ink-soft: #a8a4bc;      /* 본문 보조 — 7.81:1 */
  --ink-faint: #837e99;     /* 메타·캡션 — 4.86:1 (이보다 옅게 내리지 않는다) */

  /* ── 30% 정체성 — Electric Purple ────────
     §2: 면 전용. 글자·아이콘·얇은 선에 쓰지 않는다 (바탕 위 2.86:1). */
  --iris: #6332eb;          /* 트레이·프레임·뱃지의 '면' */
  --iris-press: #5528d4;    /* --iris 를 누른 상태 */
  --iris-soft: #a98cff;     /* '현재 배경에서 항상 보이는 보라' — 글자·아이콘·링크 (7.08:1) */
  --iris-wash: #1c1633;     /* 보라를 아주 옅게 깐 면. 섹션 블록·인용 */
  --on-iris: #f5f3ff;       /* 보라 '위에' 올라가는 글자 (6.01:1). 절대 어둡게 하지 않는다 */

  /* ── 10% 강조 — Neon Lime ───────────────
     상한이지 목표가 아니다. 한 화면에 한 점 (§2). */
  --acid: #8fff00;          /* 주인공. 버튼의 '배경' */
  --acid-deep: #8fff00;     /* '현재 배경에서 항상 보이는 초록' — 다크에선 --acid 와 같다 */
  --acid-press: #7ce600;
  --acid-wash: #1e2a0d;     /* 형광 한 점을 받쳐주는 언더레이 (면 전용) */
  --on-acid: #14140f;       /* 형광 '위에' 올라가는 글자. 테마와 무관하게 항상 어둡다 */

  /* ── 도판: 뒤집기에서 살아남은 유일한 밝은 면 (아래 절 참고) ── */
  --plate: #ebe7f5;
  --on-plate: #17151f;

  /* ── 의미색 ──────────────────────────── */
  --happy-accident: #f0906a; /* 에러. 빨강이 아니라 따뜻한 테라코타 */
  --caution: #e8b64a;
```

### 뒤집히는 토큰 vs 안 뒤집히는 토큰 (여기서 제일 많이 깨진다)

| 토큰 | 테마 따라 뒤집히나 | 왜 |
| --- | --- | --- |
| `--ink` · `--bg` · `--surface` · `--line` | ✅ 뒤집힌다 | 배경 *위에* 놓이는 것들이라 배경을 따라가야 한다 |
| `--acid-deep` | ✅ 뒤집힌다 | 이름은 '진한 초록'에서 왔지만 **실제 역할은 "현재 배경에서 항상 보이는 초록"**이다. 다크 `#8fff00` / 라이트 `#3d6b00`. 링크·포커스링에 이걸 쓰면 한 줄로 양쪽이 해결된다 |
| `--iris-soft` | ✅ 뒤집힌다 | 위와 같은 역할의 보라판. 다크 `#a98cff` / 라이트 `#4a1fc0` |
| **`--acid`** | ❌ 안 뒤집힌다 | 브랜드 색 자체다. 늘 `#8FFF00` |
| **`--iris`** | ❌ 안 뒤집힌다 | 브랜드 색 자체다. 늘 `#6332EB`. 흰 바탕에서도 6.59:1 이라 면으로는 그대로 선다 |
| **`--on-acid`** | ❌ **절대 안 뒤집힌다** | 형광 **위에** 올라가는 글자다. 배경이 테마가 아니라 형광이고, `#8FFF00`은 늘 밝다. 그러니 그 위 글자는 늘 어둡다 |
| **`--on-iris`** | ❌ **절대 안 뒤집힌다** | 같은 논리의 반대편. `#6332EB`는 늘 어두우니 그 위 글자는 **늘 밝다** |

⚠️ **토큰 이름은 그대로인데 의미만 뒤집히는 곳이 있다.** `--acid-deep` 은 라이트에서
`#3d6b00`(조용한 초록)이었지만 다크에서는 `#8FFF00` **그 자체**다. 그래서 "형광은
너무 세니까 acid-deep 을 쓰자"고 적어둔 코드가 뒤집기 한 번에 정반대가 된다 —
실제로 좋아요 하트(`components/like-button.tsx`)가 목록에서 형광 60개가 될 뻔했다.
**목록에서 '켜짐'을 나타내는 색은 형광이 아니라 `--iris-soft` 다.**

**가장 흔한 실수 둘.**

1. **형광 버튼에 `color: var(--ink)`.** 다크의 `--ink` 는 크림색(`#edebf5`)이다. **형광 위 크림색 = 1.1:1** 이라 글자가 통째로 증발한다. 반드시 `var(--on-acid)`.
2. **보라 뱃지에 `color: var(--on-acid)`.** 형광 쪽 습관을 그대로 옮기면 보라 위 `#14140F` = **2.80:1** 이라 읽히지 않는다. 보라 위에는 `var(--on-iris)`.

### 도판(plate) — 뒤집기에서 살아남은 유일한 밝은 면

```css
--plate: #ebe7f5;     /* 일러스트가 앉는 밝은 판 */
--on-plate: #17151f;  /* 그 위 글자 — 18:1 */
```

**취향이 아니라 제약이다.** 서비스·가이드 일러스트는 전부 흰 바탕에 그려져 있고
`mix-blend-multiply` 로 종이에 녹는다. multiply 는 곱셈이라 **어두운 면 위에서는
무엇을 얹어도 더 어두워지기만 한다** — 판을 `--surface` 로 바꾸는 순간 그림 아홉 장이
통째로 검게 죽는다. 그래서 그림이 앉는 판만 밝게 남겼다.

결과적으로 이게 이 시스템에서 제일 잘 된 부분이다. 어두운 페이지에서 일러스트가
**불 켜진 도판**으로 읽혀서, 카드가 "어두운 상자"가 아니라 "빛나는 것을 담은 액자"가 된다.
어두운 화면에 빛의 출처가 하나 생기는 셈이다.

⚠️ **스크린샷에는 쓰지 않는다.** 영상 썸네일은 multiply 를 안 쓰므로 밝은 판이 필요 없고,
오히려 어두운 액자(`--iris-wash`)에 앉혀야 그 위의 시리즈 라벨이 살아난다. **종류를 가르는
축이 색조에서 밝기로 옮겨간 것**이다 — 일러스트는 밝은 판, 스크린샷은 어두운 액자.
파스텔 다섯 색이 서로 구별되려면 눈이 미묘한 색조 차를 읽어야 했는데, 밝고 어두움은
곁눈으로도 갈린다. 목록이 60장이 됐을 때 실제로 작동하는 건 이쪽이다.

### 중립색은 보라 쪽으로 아주 살짝 기울인다

라이트 시절 이 자리에는 "중립색은 반드시 **따뜻하게**"가 있었다. 형광 초록 하나뿐인 시스템에서 중립에 올리브·모래 기운을 넣어야 초록이 "튀는 이물질"이 아니라 "그 종이에서 자란 한 점"이 됐기 때문이다.

**보라가 30%로 들어오면서 그 기준이 옮겨갔다.** 이제 중립은 `--iris` 쪽으로 기운다. `#121019`·`#1a1725`·`#a8a4bc` 가 전부 보라 기운을 아주 옅게 물고 있는 이유다. 순수 회색(`#888`)을 섞으면 보라 트레이가 화면에서 홀로 떠 보인다.

> **⚠️ 보라 기운과 '푸른 검정'은 다르다. 판별은 R 과 G 로 한다.**
>
> | | R | G | B | |
> | --- | --- | --- | --- | --- |
> | `#0e1116` (금지했던 푸른 검정) | 14 | **17** | 22 | G > R → 차갑다 |
> | `#121019` (이 시스템의 바탕) | **18** | 16 | 25 | **R > G** → 보라다 |
>
> B 가 제일 큰 건 둘 다 같다. **갈리는 건 R 과 G 의 순서**고, 새 바탕색을 직접 고를 일이 생기면 이 한 줄만 확인하면 된다.

### 의미색

- **성공** = 형광 초록 그 자체 (그 화면의 한 점이 된다)
- **주의** = `--caution` 따뜻한 앰버
- **행복한 사고(에러)** = `--happy-accident` 테라코타. **빨강이 아니다** — 우리는 다그치지 않는다
- **위험** = `--danger`. 진짜 되돌릴 수 없는 것(삭제 등)에만

⚠️ 다크에서 의미색은 **라이트 값보다 밝게** 잡는다. 라이트용 `#b4551f`를 어두운 바탕에 그대로 얹으면 3:1 을 못 넘는다. 위 토큰 블록의 다크 값이 그래서 라이트 값과 다르다.

## 4. 여백 — 산뜻함의 8할

색이 아니라 **여백**이 이 시스템을 숨 쉬게 만든다.

⚠️ **다크는 밀도를 감춰준다.** 어둠이 경계를 흐려서, 빽빽한 화면도 그럭저럭 봐줄 만해 보인다. 라이트일 때는 빽빽하면 바로 티가 나서 저절로 고쳐졌는데 이제는 안 그렇다. **눈으로 판단하지 말고 아래 숫자로 판단한다.**

**섹션 리듬**
- 섹션 사이 세로 여백 `--s8`(72px) ~ `--s9`(112px). *"너무 넓은데?" 싶으면 대체로 맞다.*
- 본문 최대 폭 `65ch`. 카드 그리드 최대 폭 `1120px`.
- 좌우 패딩은 모바일 `--s5`(24px), 데스크톱 `--s6`(32px) 이상.

**카드 내부**
- 패딩 `--s5`(24px) 이상. 카드 안쪽이 좁으면 아무리 둥글려도 답답하다.
- 카드 사이 간격 `--s4`~`--s5`. 카드끼리 붙이지 않는다.

**한 화면 한 이야기**
섹션 하나에 제목 하나 + 한 문단 + 그 섹션의 결과물. 두 가지를 말하고 싶으면 섹션을 나눈다. 넣고 싶은 걸 다 넣으면 Tally가 아니라 대시보드가 된다.

## 5. 타이포

**얼굴**
```css
--font-sans: Pretendard, -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo",
             "Segoe UI", "Noto Sans KR", sans-serif;
--font-mono: ui-monospace, "SF Mono", Menlo, monospace;
```
Pretendard를 1순위로 두고 시스템 폰트로 흘린다. 진지하게 붙일 거면 self-host. **Inter / Space Grotesk는 피한다** — 어디서나 보이는 기본값이라 통일감이 아니라 무개성이 된다.

**규칙**
- 본문은 65자 내외 폭. 제목엔 `text-wrap: balance`, 본문엔 `text-wrap: pretty`.
- 한국어는 `word-break: keep-all` (어절 단위로 끊기게).
- 제목 자간 `-0.02 ~ -0.03em`. 큰 글씨는 자간을 조여야 한 덩어리로 읽힌다.
- 본문 행간 `1.7` 이상. 어두운 바탕에서 행간이 좁으면 밝은 글줄끼리 서로 붙어 보인다.
- 대문자 라벨은 자간 `+0.08em`, 크기 `0.75rem`, `--ink-faint`.
- 숫자가 세로로 정렬되는 곳엔 `font-variant-numeric: tabular-nums`.
- **강조는 굵기(600~800)로 한다. 색으로 하지 않는다** — 형광은 한 점만 써야 하니까.

**⚠️ 어두운 바탕에서는 굵기를 한 단계 낮춘다.** 밝은 글자는 어두운 바탕에서 번져 보인다(halation). 라이트에서 딱 맞던 `600`이 다크에서는 `700`처럼 읽혀서, 굵기를 그대로 옮기면 화면이 통째로 무거워진다. 본문 강조는 `500~600`, 제목은 `700~800`.

**히어로 제목은 크게.** 어두운 바탕 + 넉넉한 여백의 조합은 제목이 작으면 그냥 **텅 빈 화면**이 된다. 여백이 넓어질수록 제목도 같이 커져야 균형이 맞는다.

```css
h1 { font-size: clamp(2.25rem, 6vw, 4rem); font-weight: 800; line-height: 1.12; letter-spacing: -0.03em; }
```

### 기록 줄 — 이 사이트의 등뼈

고정폭이 캡션용 장식이 아니라 **구조**다. 작업 번호(`07`)·걸린 시간(`2시간`)·날짜·회차·
읽는 시간이 전부 같은 얼굴로 나오고, 그래서 목록이 '카드 모음'이 아니라 **누가 세면서
쌓아온 기록**으로 읽힌다.

```
07 · 2시간 · 웹              서비스 카드
AX · 2026-08-25 · 6분        글 한 줄
ep 6 · 이게 되네?             영상
```

번호를 붙여도 되는 이유: **이건 진짜 순서다.** `loader.ts` 의 `assignSeq` 가 `publishedAt`
오름차순으로 매기고, 그 번호가 인스타에 올라간 편의 `#5` 와 같다. 순서가 정보가 아닌
목록에 `01 / 02 / 03` 을 붙이는 건 장식이고, 그건 하지 않는다.

**얼굴은 DM Mono 400/500** (라틴 서브셋만 자체 호스팅, 8KB×2).

- **JetBrains / Fira Code / IBM Plex Mono 를 쓰지 않는다.** 셋 다 코딩용 얼굴이라
  화면이 "개발자가 만든 개발자용 도구" 냄새를 풍긴다 — §1 의 1차 실패와 같은 종류다.
  DM Mono 는 기하학적이면서 살짝 편집물 쪽이라 터미널이 아니라 **장부**로 읽힌다.
- ⚠️ **`--font-mono` 스택 안에 Pretendard 가 있어야 한다.** DM Mono 는 라틴만 받으므로
  한글이 여기서 걸러지는데, Pretendard 가 없으면 고정폭 줄의 한글만 시스템 폰트로
  떨어져서 본문과 얼굴이 갈린다.
- ⚠️ **400/500 만 받는다.** 고정폭에 `font-bold`(700)를 걸면 브라우저가 합성해서 뭉갠다.
  숫자를 키우고 싶으면 굵기가 아니라 크기로 키운다.

**스케일** (rem)
`0.75 · 0.8125 · 0.875 · 1 · 1.125 · 1.375 · 1.75 · 2.25 · 3 · 4`

## 6. 형태 · 모션

- **모서리**: `--r-xs`(뱃지·칩) / `--r-md`(노트·인풋) / `--r-lg`(카드·트레이) / `--r-pill`(버튼). **다크로 뒤집어도 반경은 그대로 간다** — 둥근 정도를 정하는 건 밝기가 아니라 §1 의 "어려운 걸 쉬워 보이게"다.

### 반경도 예산이다 — 네 칸을 넘기지 않는다

실측 이력: 한때 화면에 **9종**(5·6·8·12·14·16·20·24·28px)이 하드코딩돼 있었고, 정작 토큰은 **한 번도 안 쓰이고 있었다.** 이렇게 되는 경로가 늘 같다 — 새 블록을 만들 때마다 "여긴 좀 더 둥글면 좋겠는데" 하고 눈으로 4px 씩 더한다. 20px 과 24px 은 나란히 놓기 전에는 구별되지 않으므로 아무도 못 알아채고, 결국 칸이 아홉이 되어 **어떤 반경도 뜻을 갖지 않게 된다.** 알약 규칙(위)과 같은 논리다.

새 반경이 필요해 보이면 **거의 항상 기존 칸 중 하나로 충분하다.** 정말 필요한 예외는 아래 하나뿐이다.

### 안쪽 반경은 취향이 아니라 계산이다 (동심원)

```
안쪽 반경 = 바깥 반경 − 그 사이 패딩
```

카드가 `--r-lg`(24px)이고 `p-3`(12px)으로 도판을 앉히면 안쪽은 **12px** 이다 (`--r-inset`). 이걸 `--r-md`(16px)나 `--r-lg`로 맞추면 두 곡선의 중심이 어긋나서, **모서리 쪽 여백만 두꺼워 보인다.** 면과 면 사이 간격이 일정해 보이지 않는 카드는 대개 여백이 아니라 이게 원인이다.

⚠️ **패딩을 바꾸면 이 값도 같이 바꿔야 한다.** `--r-inset` 이 토큰 목록에서 혼자 "계산값"이라고 적혀 있는 이유다 — 단계가 아니라서 다른 셋과 같은 자격으로 늘어나면 안 된다.

### 알약은 버튼의 것이다 — 모양도 예산이다 (§2와 같은 이유)

**`--r-pill` 은 버튼에만 쓴다.** 형광을 아무 데나 칠하면 강조가 사라지듯, 알약을 아무 데나 쓰면 "누를 수 있는 것"의 신호가 사라진다. 버튼·태그·뱃지·네비링크·필터칩이 전부 알약이면 그 화면에는 **모양이 한 개**뿐이고, 그건 디자인이 아니라 기본값처럼 보인다.

| 역할 | 모양 | 왜 |
| --- | --- | --- |
| **버튼** (이동·실행) | `--r-pill` | 알약을 보면 누를 수 있다는 뜻 — 그 뜻을 하나로 지킨다 |
| **필터 칩** (누르는 라벨) | `--r-xs` | 누르긴 하지만 버튼이 아니다. 열 개가 나란히 서므로 각진 게 덜 시끄럽다 |
| **태그 · 메타** (읽는 라벨) | 배경도 테두리도 없음 | 못 누르는 것에 상자를 씌우면 눌러본다. 고정폭 글자로 충분하다 |
| **상태 뱃지** (준비 중 · 팀) | `--r-xs` + 옅은 면 | 상태지 액션이 아니다 |
| **네비 링크** | 없음 | hover 는 색으로만. 헤더에 알약이 서면 버튼처럼 읽힌다 |

### 버튼 안에 화살표를 넣지 않는다

`→` `↗` 를 라벨 뒤에 붙이는 습관은 **한 화면에 열 개까지 늘어난다.** 열 개가 된 화살표는 방향을 알려주는 게 아니라 그냥 무늬다. 게다가 라벨이 이미 목적지를 말하고 있으면(`소스코드 보기`, `지금 써보기`) 화살표가 더하는 정보는 0이다.

예외는 **뒤로 가는 링크의 `←` 하나**다. 문서 맨 위에서 위치를 알려주는 것이라 방향이 곧 정보이고, 한 페이지에 한 번만 나온다.
- **테두리**: 검정 1px 대신 `--line`. **가능하면 테두리 없이 `--surface` 면만으로** 카드를 만든다. 선이 적을수록 조용하다.
- **층**: 다크에서 그림자는 거의 안 읽힌다. 떠 있음은 그림자가 아니라 **면 밝기 차**로 만든다 — `--bg` → `--surface` → `--surface-2` 순으로 한 칸씩 올린다. 그림자 토큰은 진짜 떠 있어야 할 것(드롭다운·모달)과 라이트 대응에만 남겨둔다.
- **hover**: 카드는 `translateY(-2px)` + `--shadow-md` 정도. 색을 바꾸지 않는다.
- **모션**: 180–280ms `cubic-bezier(0.4, 0, 0.2, 1)`. 튀는 스프링/바운스 금지(밥 아저씨는 안 튄다). `prefers-reduced-motion: reduce`는 반드시 존중.

| **상태 뱃지** (준비 중 · 팀 · 앱스토어) | 기본은 **중립**이다 — `--surface-2` 면 + `--ink-soft` 글씨 + `--r-xs` (§6 — 알약 아님). 뱃지가 세 종류인데 셋 다 보라를 주면 격자 전체에 보라가 흩뿌려져서, 정작 큰 면이 해야 할 30%가 알갱이로 쪼개진다. **의미가 가장 무거운 하나만**(여기서는 `팀`) `--iris` + `--on-iris` 를 갖는다. ⚠️ 보라 뱃지에 `--on-acid`를 쓰지 않는다 — 보라 위 `#14140F` 는 2.80:1 이라 안 읽힌다 (§3) |
| **인풋** | `--surface-2` 배경, `--line-strong` 테두리, `--r-md`. 포커스 시 `--acid` 링 |
| **에러 배너** | `--surface` 배경 + 좌측 `--happy-accident` 바 + [무슨 일 / 어떻게 하면 됨]. 아이콘으로 겁주지 않는다 |
| **칩 · 라디오 · 체크박스 · 슬라이더** | `--r-xs` (알약 아님 — §6). **형광 금지 (§2 예산). 보라 면도 금지** — 칩이 10개면 트레이가 10개가 돼서 30%가 60%를 덮는다. 선택됨 = `--surface-2` 배경 + `--ink` 글씨. `accent-color`도 `--ink-soft`로 |
| **태그 · 메타 라벨** | 상자를 씌우지 않는다 (§6). 고정폭 `--ink-faint` 글자 + `·` 구분. 누를 수 있는 태그는 밑줄 hover 로만 알린다 |
| **링크** | 본문 안에서는 `--iris-soft` + 밑줄. 형광을 링크에 쓰지 않는다 — 한 문단에 링크가 셋이면 형광이 셋이 된다 (§2) |
| **포커스 링** | `outline: 2px solid var(--acid-deep); outline-offset: 2px`. 다크에서 `--acid-deep` 은 `#8FFF00` 그 자체라(§3) 라이트 대응까지 이 한 줄로 끝난다 |
| **푸터** | `--iris-wash` 띠. 어두운 바탕에서는 페이지가 어디서 끝나는지가 안 보인다 — 띠 하나가 문서를 닫는다. 큰 보라 슬랩은 페이지당 하나뿐이라, **모든 페이지에 있는** 푸터가 30% 층을 사이트 전체의 구조로 만든다. ⚠️ 이 면 위에서 `--ink-faint` 는 4.1:1 이라 글자는 전부 `--ink-soft` |

### 형광 한 점은 '누를 것'이 아니라 '그 화면이 하려는 말'에 붙는다

라이트 시절 이 규칙은 사실상 "Primary 버튼 = 형광"이었다. 어두운 바탕에서는 그게
안 맞는다 — 형광 알약은 **14.79:1** 이라 페이지에서 가장 큰 소리를 내고, 그러면
화면이 하려는 말보다 이동 버튼이 먼저 읽힌다.

그래서 규칙을 한 칸 위로 올린다. **묻는 것은 "이 화면의 주인공 액션은 무엇인가"가
아니라 "이 화면이 하려는 단 하나는 무엇인가"다.** 대개는 여전히 버튼이지만, 아닐 때가 있다.

| 화면 | 형광이 붙은 곳 | Primary 버튼 |
| --- | --- | --- |
| 랜딩 | **제목 뒤의 커서** — 이 사이트가 하려는 말은 "이게 되네?" 다섯 글자다 | `--iris` |
| 서비스 상세 | "지금 써보기" — 이 페이지의 존재 이유가 실제 앱으로 보내는 것이다 | 그게 형광 |
| 로그인 | 제출 버튼 | 그게 형광 |

⚠️ **둘 다 형광으로 만들지 않는다.** 커서와 버튼이 같은 화면에 형광으로 서면 그 순간
예산이 깨진다(§2). 랜딩의 버튼이 보라인 건 양보가 아니라 **그래야 보라 30%가 실제로
자리를 차지하기 때문**이기도 하다.

### 브랜드 마크 — 말풍선과 스파크

**서비스마다 로고를 새로 그리지 않는다.** 워드마크 앞에 붙는 **마크 하나**가 모든 서비스의 공통 얼굴이다. **생각(말풍선)** 옆으로 **스파크 세 획**이 튄 형태다 — §1 의 60/30/10 이 마크 안에서 한 번 더 반복된다: 어두운 테두리, 보라 말풍선, 형광 스파크.

#### 실측 치수 — 다시 그릴 일이 생기면 여기서 시작한다

말풍선은 **채워진 원이 아니라 두꺼운 링**이다 (`public/brand/source/logo-render.png` 실측, 원본 1536×1024 기준).

| | 값 | 비율 |
| --- | --- | --- |
| 링 중심 | (704, 564) | — |
| 안쪽 반지름 | **178px** | 바깥의 0.46 |
| 바깥 반지름 | **385px** | — |
| 링 벽 두께 | 207px | 바깥지름의 27% |
| 꼬리 | **315°** 방향, 끝 r=535 | 바깥 반지름의 1.39배 |
| 꼬리 각폭 | 300°–330° | 약 30° |
| 스파크 무리 | 중심에서 38°, r≈505 | 링 바깥에 살짝 겹친다 |

**가운데 구멍이 이 마크의 핵심이다.** 채워진 원반으로 그리면 형태가 통째로 달라진다 — 실제로 한 번 그렇게 그렸다가 되돌렸다.

> **⚠️ 렌더에서 형태를 눈으로 읽지 말 것. 여기서 반드시 속는다.**
>
> 원본 렌더는 스파크 광륜이 워낙 세서, **링의 오른쪽 위가 잘려 보인다.** 눈으로는 홈(notch)이 파인 것처럼 보이고 실제로 그렇게 그렸었다. 픽셀을 찍어보면 아니다 —
>
> - 스파크 반대편(180°): `#130b1b` 가 r=380 까지 **일정**하게 이어진다
> - 스파크 쪽(30°): 같은 보라가 r=340 까지 가다가 `#25281b` → `#3b4f16` 으로 **초록이 덮는다**
>
> 섞이는 중간색이 나오면 그건 잘린 게 아니라 **가려진 것**이다. 링은 끊김 없이 이어진다. 형태를 확정할 땐 각도별로 반지름을 훑어 색을 찍어볼 것.
>
> 같은 이유로 **렌더에서 색을 빼오지도 말 것.** 렌더의 말풍선은 한가운데가 `#000000` 이고 가장 밝은 픽셀조차 `#1d1a1f` 다 — 보이는 보라는 면이 아니라 **광륜**이다. 그 값을 그대로 마크에 넣으면 어두운 바탕에서 1.1:1 로 사라지고 흰 바탕에서는 브랜드 색이 하나도 안 남는다. 마크의 말풍선은 `--iris`(`#6332EB`)다.

> **폐기 이력이 셋 있다.** ①**초록 점 하나** — 만들 것도 없고 어떤 이름에도 붙었지만, 기억에 남는 게 색뿐이라 "형광 초록 쓰는 사이트" 이상이 되질 않았다. ②**캐릭터** — 얼굴은 남지만 16px에서 눈·입이 전부 뭉개져서 파비콘용으로 머리만 따로 그려야 했다. 마크를 두 벌로 관리하는 순간 둘은 반드시 어긋난다. ③**ㄱ 과 점** (~2026-08) — 형태는 끝까지 버텼지만, 채널이 "만드는 사람"에서 "AX하는 창업가"로 옮겨가면서 **자음 하나가 더는 그 얘기를 하지 않았다.** 지금 마크에서 말풍선은 생각을, 스파크는 그 생각이 실행으로 튀는 순간을 맡는다.

#### 스파크가 마크다. 말풍선은 그 스파크가 앉는 자리다

측정값이 역할을 정한다.

| | `#121019` 위 | 흰 바탕 위 |
| --- | --- | --- |
| 형광 스파크 `#8FFF00` | **14.79:1** | 1.27:1 → 어두운 테두리가 받친다 |
| 보라 말풍선 `#6332EB` | **2.86:1** | 6.59:1 |

말풍선은 **자기 바탕 위에서 2.86:1** 이다. 이건 실수가 아니라 **의도된 조용함**이다 — 로고는 WCAG 대비 기준의 명시적 예외이고(1.4.11), 이 마크에서 "읽히는" 일은 스파크가 맡는다.

⚠️ **그래서 말풍선만 떼어 쓰지 않는다.** 스파크가 빠지면 어두운 바탕에서 형태가 통째로 사라진다. 반대로 스파크만 떼어 쓰는 건 된다 — 아주 작은 자리(16px 미만, 커서, 리스트 불릿)에서는 그게 오히려 맞다.

#### 2겹 구조가 이 마크의 전부다

같은 도형을 **두 번 겹쳐 그린다.** 아래에 어두운 색으로 굵게, 위에 제 색으로 가늘게.

```svg
<!-- 1) 어두운 바닥: 모든 도형을 먼저. stroke 를 굵게 줘서 사방으로 삐져나오게 -->
<g fill="#121019" stroke="#121019" stroke-width="3" stroke-linejoin="round" stroke-linecap="round">…</g>
<!-- 2) 색 본체: 같은 도형, stroke 를 1.5 가늘게 -->
<circle … fill="#6332EB" stroke="#6332EB" stroke-width="1.5"/>
<path   … stroke="#8FFF00" stroke-width="3"/>
```

굵기 차의 절반(여기선 0.75px)이 그대로 **어두운 테두리**가 된다. 도형을 두 벌 그리는 대신 `stroke-width` 만 바꾼다. **어두운 층을 전부 먼저 깔고 색 층을 전부 나중에** 올리는 순서가 중요하다 — 도형별로 번갈아 그리면 테두리가 옆 도형을 덮는다.

**왜 이래야 하나.** `#8FFF00`은 흰 바탕에서 **1.27:1**이다(§3). 외곽선 없이 형광만 놓으면 밝은 화면에서 스파크가 통째로 사라진다. 어두운 테두리가 대비를 만들어주기 때문에 **한 벌로 어두운 사이트·흰 카톡 말풍선·인쇄물 양쪽에서 다 읽힌다.**

⚠️ 테두리 색은 `#121019` — **이 시스템의 바탕색 그 자체**다. 그래서 사이트 위에서는 테두리가 보이지 않고(같은 색), 흰 바탕에서만 나타난다. 검정(`#000`)으로 바꾸지 않는다.

#### 크기별 두 파일

| 파일 | 쓰는 곳 | 차이 |
| --- | --- | --- |
| `public/brand/mark.svg` (= `app/icon.svg`) | 32px 이상, 앱 아이콘, 인쇄 | 기본 비율 |
| `public/brand/mark-sm.svg` | 헤더, 파비콘, 16~28px | 스파크 획을 굵히고 점을 키운다. 말풍선은 **반대로 살짝 줄여** 자리를 내준다 |

같은 마크의 **광학 보정판**이지 다른 마크가 아니다. 새 크기가 필요해도 도형을 새로 만들지 말고 굵기만 조정한다.

#### 렌더는 자산이 아니다

`public/brand/source/` 의 PNG 두 장(`logo-render` · `logo-scale-test`)은 **키비주얼 렌더**다. 1536×1024 에 글로우가 구워져 있고, 마크가 프레임 가운데도 아니다. 여기서 가져올 것은 **형태와 배치**뿐이고, 실제로 쓰는 파일은 위의 SVG 두 개다.

**비율은 렌더 그대로 옮겼다** (위 실측 표). 형태를 "정리"하고 싶은 유혹이 들어도 링 두께와 꼬리 각도는 건드리지 않는다 — 그게 이 마크를 알아보게 하는 전부다.

⚠️ 바꾼 것은 **두 가지뿐**이고 둘 다 이유가 있다.

- **글로우를 뺐다.** 16px 에서 광륜은 회색 얼룩이 되고, UI 에서 형광 글로우는 §2 가 금지한다. 렌더는 어두운 데서 이 마크를 **찍은 사진**이고, SVG 는 마크 자체다.
- **소형 보정판(`mark-sm.svg`)에서만 스파크 획을 굵히고 링 벽을 얇혔다.** 원본 비율로 16px 을 그리면 스파크 획이 1px 미만이 되고 링 구멍이 메워진다. 기본판은 실측 비율 그대로다.

**규칙**
- **투명 배경.** iOS 앱 아이콘만 투명을 못 살리므로 `#121019` 타일 위에 얹는다.
- 크기는 워드마크 글자 크기의 **1.5배 내외**.
- **16px로 렌더해서 확인하기 전엔 완성이 아니다.**
- 마크의 형광은 §2의 예산에 넣지 않는다 — 늘 같은 자리에 고정이라 흩어지지 않는다.
- **글로우 0개.** 렌더에 있는 halo 를 SVG 로 옮기지 않는다 (§2).

**여전히 유효한 것:** 형광으로 **선을 긋거나 작은 도형을 찍는 건** 라이트 대응에서 여전히 금지다(§3). 이 마크가 예외인 건 어두운 외곽선을 업고 있기 때문이지, 형광이 밝은 바탕에서 괜찮아졌기 때문이 아니다.

### 서명 — made by kyulolong

모든 서비스에 조용히 넣는다. 헤더 우측 끝 또는 페이지 맨 아래.

```html
<span class="credit">made by kyulolong</span>
```
```css
.credit {
  font-family: var(--font-mono);
  font-size: 0.7rem;
  letter-spacing: 0.06em;
  color: var(--ink-faint);
  opacity: 0.7;
  white-space: nowrap;
  transition: opacity 0.2s ease-out;
}
.credit:hover { opacity: 1; }
```

- **중립색으로.** 서명은 자랑이 아니라 **낙관(落款)**이다 — 형광을 쓰지 않는다. 형광은 사용자가 할 일에만.
- 소문자 그대로, 모노스페이스. 대문자로 키우지 않는다.
- 평소엔 흐릿하게, 마우스를 올리면 또렷하게. 찾으면 거기 있고, 안 찾으면 안 보인다.

## 8. 페이지 뼈대 (랜딩·소개 페이지용)

Tally스러운 페이지는 대체로 이 순서다. 순서를 지키면 반은 먹고 들어간다.

1. **얇은 헤더** — 브랜드 마크 + 링크 두세 개. 배경은 `--bg`, 스크롤 시에만 아래 `--line` 1px. 헤더에 버튼을 넣지 않는다(형광이 두 개가 된다).
2. **히어로** — 큰 제목 한 줄 + 한 문단 + **Primary 버튼 하나**. 여기가 형광 한 점이다. 위아래 여백 `--s9`.
3. **결과물** — 목록·그리드·스크린샷. 히어로 다음에 바로 실물이 나와야 한다. 설명이 먼저 나오면 지루하다.
4. **큰 보라는 페이지에 딱 한 번** — `--iris` 로 꽉 채운 슬랩 하나. **이 층이 §1 의 30%를 실제로 채우는 자리다.**
   ⚠️ **두 번 치면 힘이 반이 된다.** 실제로 랜딩에서 진한 슬랩과 옅은 슬랩을 위아래로 붙여봤더니
   덩어리 둘이 쌍둥이로 읽히고 둘 다 죽었다. 지금은 진한 것 하나만 두고, 그 다음 절은 **가는 선
   하나로 열고 여백으로 받는다** — 조용한 자리가 있어야 그 하나가 크게 들린다.
5. **푸터가 페이지를 닫는다** — `--iris-wash` 띠 (§7). 어두운 바탕에서는 문서의 끝이 안 보인다.
6. **푸터 내용** — 링크 + 서명. 조용하게.

**하지 않을 것:** 히어로 배경에 그라데이션 메시, 스크롤 패럴랙스, 자동 재생 캐러셀, 숫자 카운트업 애니메이션. 전부 "열심히 꾸민 티"가 나고, 이 시스템은 그 반대편에 있다.

## 9. 말투 — 가장 중요한 부분

색은 갈아끼울 수 있지만 말투가 곧 그 서비스의 인격이다. 밥 아저씨는 **여기에** 산다.

**원칙**
1. **절대 다그치지 않는다.** 사용자 탓하는 문장 금지.
2. **실수 = 행복한 사고.** 항상 되돌릴 수 있다고 알려준다.
3. **어려운 걸 쉽게 말한다.** 전문용어 대신 사람 말. (사용자는 *알림*을 관리하지, *웹훅 설정*을 관리하지 않는다)
4. **성공은 담백하게.** "참 쉽죠?"는 강력하지만 **서비스당 한 번만** 아껴 쓴다. 남발하면 유치해진다.
5. **차분한 존댓말.** 느낌표 남발 금지. 이모지는 있어도 한두 개.

**Before → After**

| ❌ 이렇게 쓰지 않는다 | ✅ 이렇게 쓴다 |
| --- | --- |
| "잘못된 입력입니다" | "이 형식이면 바로 돼요: 010-1234-5678" |
| "오류: 위치를 잃었습니다. 대본으로 돌아오세요" | "잠깐 놓쳤어요. 편하게 계속 읽으시면 다시 따라갈게요" |
| "모델을 찾을 수 없음 (404)" | "한국어 모델이 아직 없어요. `npm run get-model` 한 번이면 준비 끝이에요" |
| "필수 항목입니다" | "여기만 채우면 시작할 수 있어요" |
| "저장에 실패했습니다" | "저장이 안 됐어요. 방금 쓰신 내용은 그대로 있으니 다시 눌러보세요" |
| "정말 삭제하시겠습니까?" | "지울까요? 이건 되돌릴 수 없어요" |

**핵심 차이:** 나쁜 문구는 *사용자에게 책임을 넘긴다*("돌아오세요"). 좋은 문구는 *서비스가 책임지고 안심시킨다*("제가 다시 따라갈게요").

## 10. 접근성 (색이 세 겹이면 특히 중요)

- 본문 대비 **4.5:1**, 큰 글씨(18px+/굵은 14px+) **3:1** 이상. §3 토큰은 전부 이 기준을 넘게 골랐다.
- **`--iris`를 글자·아이콘·얇은 선으로 쓰지 않는다** — 바탕 위 **2.86:1** 이라 큰 글씨 기준(3:1)조차 못 넘는다. 보라가 글자여야 하면 `--iris-soft`(7.08:1).
- **보라 면 위 글자는 `--on-iris`(밝게), 형광 면 위 글자는 `--on-acid`(어둡게).** 둘이 정반대라 한쪽 습관을 그대로 옮기면 반드시 깨진다 (§3).
- **`--ink-faint`보다 옅은 글자색을 새로 만들지 않는다.** 어두운 바탕에서 "예쁘게 은은한 회색"은 거의 항상 4.5:1 미만이다.
- **다크가 기본이라고 라이트 대응을 빼지 않는다.** 고대비 모드·인쇄·화면 캡처가 전부 밝은 바탕으로 떨어지고, `--acid`는 흰 바탕에서 1.27:1 이라 그 순간 통째로 사라진다.
- **색만으로 정보를 전달하지 않는다.** 형광이 하나뿐이라 더더욱 — 모양·라벨·아이콘을 같이 준다.
- 포커스 링은 항상 보이게(`--acid-deep`). 키보드로 전체 조작 가능하게.
- `prefers-reduced-motion` 존중.

## 12. 모바일 — 이 문서가 오래 비워둔 자리

이 절이 생기기 전까지 이 문서에서 "모바일"은 §4 의 좌우 패딩 한 줄이 전부였다. 브레이크포인트도, 탭 타깃 최소치도, 하단 바 얘기도 없었다. 그래서 실제로 다음이 깨져 있었다 — 375px 헤더 넘침, `env(safe-area-inset-*)` 가 전부 0, 24px 짜리 탭 타깃, 화면을 밀어내는 URL 한 줄. **적어두지 않으면 다음 사람이 같은 자리에서 다시 넘어진다.**

### 기본 방향은 이미 맞다 — 착각하지 말 것

무접두 Tailwind 클래스가 **모바일** 레이아웃이고 `sm:`/`md:`/`lg:` 는 위로만 올라간다. `max-*:` 접두를 쓰지 않는다. 그리드는 전부 `grid-cols-1` 에서 출발한다. 이건 이미 지켜지고 있으므로 "모바일 퍼스트로 갈아엎자"는 진단이 나오면 그건 잘못 짚은 것이다. 손볼 것은 아래 넷이다.

### 1. 하단 고정 네비 (md 미만)

상단 헤더는 `md` 부터만 링크를 그린다(`hidden md:flex`). 그 아래에서는 이동을 하단 바가 맡는다 — 엄지가 닿는 자리이기도 하다.

| 규칙 | 왜 |
| --- | --- |
| **형광을 쓰지 않는다** | 375px 대문에서 히어로의 형광 버튼과 바가 같은 화면에 들어온다. §11 의 "스크린샷 찍고 초록을 센다"에서 바로 걸린다 |
| "상태 점" 예외에 기대지 않는다 | §2 의 예외는 **고정된 것**을 위한 것이다. 활성 탭은 페이지를 옮길 때마다 자리를 옮긴다 — §2 가 세는 '흩어짐'이 화면이 아니라 시간에 퍼져 있을 뿐이다 |
| **알약도 채운 상자도 없다** | §6 — 네비 링크는 모양이 없다 |
| 활성 표시는 **세 채널** | 굵기(500→600) + 잉크 농도(`--ink-faint`→`--ink`) + 바의 위 선에 얹히는 2px 눈금. 굵기는 흑백에서도 색맹에서도 살아남는 유일한 채널이라 §10 을 이걸로 만족시킨다 |
| **아이콘 없이 글자만** | §6 이 버튼 안 화살표를 금지한 논리 그대로 — 라벨이 목적지를 말하면 그림이 더하는 정보는 0이다. 게다가 "생각들"·"만든 것"에는 관습 아이콘이 없어서 은유를 새로 만들어야 하고, 그렇게 만든 넉 장은 16px 에서 뭉개진다 (§7 의 캐릭터 마크가 그래서 빠졌다) |
| 칸은 **셋**까지 | 375px 에서 칸당 109px. 다섯이면 65px 라 라벨이 빽빽해진다. 넘치는 목적지는 푸터가 받는다 |

`z-40` (헤더의 `z-50` 보다 낮게). 안전영역 패딩은 **바 자신**이 갖는다 — 안쪽 래퍼에 주면 반투명 배경 아래 흰 띠가 남는다.

### 2. 안전영역 — 스위치가 하나 있다

```ts
// app/layout.tsx
export const viewport: Viewport = { viewportFit: "cover", /* … */ };
```

**이게 없으면 `env(safe-area-inset-*)` 가 전부 `0px` 로 풀린다.** Next 의 기본 viewport 에는 `viewport-fit` 이 없다. 하단 바의 홈 인디케이터 여백도, 가로 모드의 노치 여백도 이 한 줄에 달려 있다.

`maximumScale` / `userScalable: false` 는 **넣지 않는다** — §10 과 WCAG 1.4.4 위반이다. 넘침은 확대를 막아서가 아니라 구조로 고친다.

```css
body { padding-bottom: var(--nav-space); }   /* main 이 아니라 body 다 — 푸터가 main 밖에 있다 */
html { -webkit-text-size-adjust: 100%; }     /* 가로 모드에서 글자가 혼자 커지는 것 */
html { -webkit-tap-highlight-color: rgb(237 235 245 / .10); }  /* transparent 로 죽이지 않는다 */
```

탭 하이라이트를 `transparent` 로 지우지 않는 이유: JS 로 만든 press 상태가 없는 사이트에서는 이게 **유일한 터치 피드백**이다. iOS 기본값의 차가운 파랑만 바탕에 맞는 색으로 바꾼다. ⚠️ **다크로 뒤집으면 부호가 반대가 된다** — 어두운 바탕에는 어두운 오버레이가 안 보이므로 밝은 쪽으로 얹는다.

### 3. 탭 타깃 44px

```
inline-flex items-center min-h-11   +   md:min-h-0
```
`md:` 에서 되돌리는 게 핵심이다 — 포인터 환경의 촘촘한 배치는 원래 의도한 것이다.

**예외 하나**: 격자 안의 작은 컨트롤(좋아요 버튼)은 박스를 키우면 60장짜리 목록이 통째로 높아진다. 그때는 의사요소로 히트 영역만 넓힌다 — `relative after:absolute after:-inset-x-3 after:-inset-y-2.5 md:after:hidden`.

⚠️ 폼 입력에는 `text-*` 클래스를 붙이지 않는다. 16px 를 상속받아야 iOS 가 포커스에서 확대하지 않는다.

### 4. `word-break: keep-all` 에는 짝이 필요하다

`body { word-break: keep-all }` 은 한글 어절을 안 쪼개는 대신 **끊을 자리가 없는 라틴 토큰**(URL·이메일·명령어)도 통째로 안 쪼갠다. 그런 토큰 하나가 화면보다 길면 페이지 전체가 가로로 밀린다.

```css
body { overflow-wrap: break-word; }   /* anywhere 가 아니다 */
```
`anywhere` 는 min-content 계산에 끼어들어 칩·`w-fit` 요소를 **전역에서** 쪼그라뜨린다. 정말 안 들어가는 한 곳(원시 URL 을 그리는 자리)만 `wrap-anywhere` 로 국소 처리한다.

**빠른 검사:** 모든 페이지에서 `document.documentElement.scrollWidth === clientWidth`.

### 안 하는 것

- 스크롤 시 헤더 숨기기 — §6·§8 이 금지하는 "열심히 꾸민 티"다
- 모바일에서 필터 레일 sticky — 칩이 서너 줄까지 감기면 그 높이가 화면 위에 상시로 박힌다 (`md:sticky` 로 두는 이유)
- 확대 차단, 자동 넘어가는 캐러셀

## 11. 새 서비스 체크리스트

- [ ] **마크를 16px로 렌더해서 형태가 살아있는지 봤다** (§7 — 여기서 대부분 깨진다)
- [ ] **"이 화면의 형광 한 점은 무엇인가?"** — 하나만 정했다

- [ ] **보라 30%가 실제로 채워졌나?** 트레이·프레임·뱃지가 하나도 없으면 화면이 검정과 형광 두 겹이고, 그건 §1 이 적어둔 1차 실패다
- [ ] **`--iris`를 글자·테두리·얇은 선에 쓰지 않았다** (§2 — 면 전용, 2.86:1)
- [ ] **보라 면 위 글자가 `--on-iris`인가?** `--on-acid`(어두운색)를 옮겨 쓰면 2.80:1 이다 (§3)
- [ ] **글로우가 0개다.** 형광에 `box-shadow`/`text-shadow`를 씌운 곳이 없다
- [ ] **일러스트가 앉는 판이 `--plate`(밝은 면)인가?** 어두운 면 위에 `mix-blend-multiply` 를 얹으면 그림이 통째로 사라진다 (§3)
- [ ] **고정폭에 `font-bold`를 건 곳이 없나?** DM Mono 는 400/500 만 받는다 — 700 은 합성되어 뭉갠다 (§5)
- [ ] **큰 보라 슬랩이 페이지에 하나인가?** 둘이면 쌍둥이로 읽혀서 둘 다 죽는다 (§8)
- [ ] 중립색이 보라 쪽으로 기울었나? **R > G 인지 한 번 본다** — G > R 이면 푸른 검정이고 실패다 (§3)
- [ ] 포커스 링이 `--acid-deep`인가? (다크·라이트 양쪽을 이 한 줄이 해결한다 — §3)
- [ ] **여백이 넉넉한가?** 섹션 사이가 72px 이상인가? 카드 패딩이 24px 이상인가? (§4)
- [ ] **히어로 제목이 충분히 큰가?** 여백만 넓고 글씨가 작으면 빈 화면이 된다 (§5)
- [ ] 에러 문구를 '행복한 사고'로 다시 썼나? (사용자 탓 X)
- [ ] 다크/라이트 둘 다 확인했나? (한쪽만 쓸 거면 그건 *선택*이어야지 *누락*이면 안 된다)
- [ ] **남의 디자인을 요청 없이 바꾸지 않았다.** 색을 바꾸랬으면 색만 바꾼다
- [ ] **375px 에서 봤다** (§12). 가로 스크롤이 없나? 탭 타깃이 44px 인가? 하단 바에 형광이 0개인가?
