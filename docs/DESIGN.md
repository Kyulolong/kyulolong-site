# 디자인 시스템 — 흰 종이 위의 형광 초록 한 점

모든 서비스에 같은 얼굴을 주기 위한 문서. 새 프로젝트를 시작할 때 §3의 토큰 블록을 복사해서 시작하고, 판단이 갈릴 때는 §1의 원칙으로 돌아온다.

> **2026-08 개정.** 기본값을 **다크에서 라이트로 뒤집었다.** 이 시스템은 이제 *밝고 산뜻하고 심플한* 쪽에 선다. 형광 한 점 규칙(§2)과 말투(§9)는 그대로다.

---

## 1. 무드 — 왜 이렇게 생겼나

세 개의 축이 있다.

**밥 아저씨 (Bob Ross)**
> "참 쉽죠?" · "실수란 없어요. 그저 행복한 사고죠."

차분하고, 따뜻하고, 절대 다그치지 않는다. **어려운 것을 쉬워 보이게** 만든다. 사용자가 뭘 잘못해도 세상은 안 무너진다.

**Tally 같은 여백**
정보를 채우지 않고 **덜어낸다.** 한 화면에 한 가지 이야기, 한 개의 액션. 큰 글씨, 넉넉한 여백, 둥근 면, 옅은 파스텔 종이. 화려해서 좋아 보이는 게 아니라 **숨 쉴 틈이 있어서** 좋아 보인다.

**Acid Green `#8FFF00`**
형광의 에너지. 살아있다는 신호. *세상은 살아볼만하다.*

### 한 문장으로

> **흰 종이처럼 비우고, 붓끝의 한 점만 형광으로.**

밝은 바탕은 "쉬워 보인다"를 만들고, 형광 한 점은 "기억에 남는다"를 만든다. 둘 다 필요하다.

### 왜 라이트로 뒤집었나 (실수 이력)

처음엔 다크 베이스였다. 형광 초록이 어두운 바탕에서 가장 예쁘게 터지니까 자연스러운 선택처럼 보였다. 그런데 **다크 베이스 + 형광 = 사이버펑크**로 읽힌다. 밥 아저씨 축이 완전히 죽고, "개발자가 만든 개발자용 도구" 냄새가 난다.

밝은 바탕으로 뒤집으면 형광은 **덜 예쁘지만 더 정확하다.** 캔버스가 조용해지니 한 점이 더 크게 들리고, 서비스 전체가 "누구나 써도 되는 것"처럼 보인다. 이 시스템이 파는 건 형광의 예쁨이 아니라 **접근 가능함**이다.

**다크 모드는 버리지 않았다.** 다만 이제 *기본*이 아니라 *대응*이다 (§3).

## 2. 형광 예산 — 이 시스템의 전부

> ### 한 화면에 형광 초록은 딱 한 곳.
> 나머지는 전부 따뜻한 중립색.

새 화면을 만들 때 스스로에게 묻는다: **"이 화면에서 형광이 찍힐 그 한 점은 어디인가?"** 보통 그 화면의 주인공 액션 하나다. 정하고, 나머지는 다 중립으로 눕힌다.

이 규칙은 **말은 쉽고 지키기는 어렵다.** "강조 색"이라고 생각하는 순간 버튼·칩·라디오·슬라이더·링크밑줄·로고에 하나씩 붙어서, 정신 차리면 화면에 형광이 8개다. 그러면 **눈이 아프다.** 그래서 예산을 숫자로 못 박는다.

| | |
| --- | --- |
| ✅ **형광 1개** | 그 화면의 주인공 액션 (Primary 버튼 / 지금 주목할 대상) |
| ✅ 예외: 브랜드 마크의 새싹 | 정체성이다. 작고 늘 같은 자리에 고정이라 주목을 다투지 않는다 (§7). 글로우만 금지 |
| ✅ 예외: 작은 상태 점 | ~8px 인디케이터. 정보를 전달하고 면적이 없다 |
| ✅ 예외: 포커스 링 | 키보드로 눌렀을 때만 잠깐 나타난다 (접근성) |
| ❌ 선택된 칩 · 라디오 · 체크박스 · 슬라이더 | `accent-color`에 무심코 넣게 되는 최대 함정. 중립으로 |
| ❌ 링크 밑줄 · 구분선 · 가이드선 | 조용한 참고물이다. 중립으로 |

**고정된 것 vs 흩어진 것.** 로고처럼 *늘 같은 자리에 고정된* 형광은 눈이 곧 배경으로 처리해서 피로하지 않다. 진짜 피로는 *여기저기 흩어진* 형광(선택된 칩, 슬라이더 손잡이, 밑줄…)에서 온다 — 시선이 매번 "저건 뭐지?" 하고 붙잡히기 때문. 그래서 예산은 **개수**가 아니라 **흩어짐**을 센다.

### 파스텔 종이는 예산에 안 들어간다 (중요)

밝은 바탕으로 오면서 **파스텔 틴트 면**(§3의 `--paper-*`)이 새로 생겼다. Tally스러운 산뜻함의 대부분이 여기서 나온다. 이건 형광 예산과 **별개**다 — 조건이 있다.

| | |
| --- | --- |
| ✅ **면(배경)으로만** | 카드·섹션·히어로 블록의 배경. "색깔 있는 종이"다 |
| ✅ 카드 하나에 하나 | 한 카드 안에서 틴트를 두 개 섞지 않는다 |
| ❌ 글자 · 아이콘 · 테두리 · 버튼 | 여기에 쓰는 순간 그건 종이가 아니라 **강조색**이고, 형광과 싸운다 |
| ❌ 채도 올리기 | 틴트는 채도 ~8% 이하다. 진해지면 종이가 아니라 스티커가 된다 |

**판별법:** 그 색을 흑백으로 바꿨을 때 레이아웃이 그대로면 종이다. 뭔가 안 읽히면 그건 강조색이었던 거고, 규칙 위반이다.

### 일러스트가 여러 장 깔릴 때 (카드 그리드)

서비스 카드마다 일러스트가 있고 그 안에 각각 형광이 한 점씩 있으면, 그리드 한 화면에 형광이 여섯 개가 된다. 예산 위반처럼 보이지만 아니다 — §2가 세는 건 개수가 아니라 **흩어짐**이고, 격자 위에 규칙적으로 놓인 점은 로고처럼 **고정 패턴**으로 읽힌다. 눈이 "저건 뭐지?" 하고 매번 붙잡히지 않는다.

**단, 조건이 붙는다.**

- 일러스트 **한 장 안에는 형광이 정확히 하나.** 두 개가 되는 순간 그 카드 안에서 시선이 갈라진다.
- **카드 밖 UI에는 형광을 하나도 더 두지 않는다.** 선택된 칩, featured 표시 점, 태그, 링크 — 전부 중립. 격자 밖으로 새는 형광 하나가 패턴을 깨고 화면을 어지럽게 만든다.
- 히어로의 Primary 버튼은 이 격자 **바깥의 한 점**이라 따로 계산한다. 그래서 랜딩에는 형광이 "버튼 1 + 격자 패턴" 두 층으로만 존재한다.

*"카드마다 대표작이라고 초록 표시를 하나씩 찍고 싶다"는 유혹이 여기서 온다. 찍지 마라 — 그 점들은 격자에 안 맞아서 진짜로 흩어진다. 대표작은 이미 '목록 맨 앞'이라는 형태로 드러나 있다.*

### 글로우(halo) 금지

```css
box-shadow: 0 0 24px rgba(143, 255, 0, 0.3); /* ❌ 절대 */
text-shadow: 0 0 26px rgba(143, 255, 0, 0.4); /* ❌ 절대 */
```

**형광색에 글로우를 씌우면 눈이 찔린다.** `#8FFF00`은 이미 대비가 충분해서 **색 하나로 튄다.** 빛나 보이게 하고 싶은 유혹이 들면, 글로우 대신 **주변을 더 조용하게** 만든다.

## 3. 색

### 먼저 알아야 할 사실: `#8FFF00`은 '글자색이 아니다'

측정값이 규칙을 정한다.

| 조합 | 대비 | 판정 |
| --- | --- | --- |
| `#8FFF00` 글자 / 흰 배경 | **1.27 : 1** | ❌ 사실상 안 보임. 절대 금지 |
| 검정 글자 / `#8FFF00` 배경 | **14.5 : 1** | ✅ 버튼에 최적 |
| `#8FFF00` 글자 / 어두운 배경 | **14.7 : 1** | ✅ 다크 모드에서만 |

**라이트가 기본이 된 지금, 형광은 거의 항상 '배경'이다.** 글자로 쓰고 싶으면 `--acid-deep`(6.4:1)을 쓴다.

### 토큰 (복붙용)

```css
:root {
  color-scheme: light;

  /* ── 형광 한 점 ───────────────────────── */
  --acid: #8fff00;          /* 주인공. 버튼·칩의 '배경'으로 쓴다 */
  --acid-deep: #3d6b00;     /* '현재 배경에서 항상 보이는 초록' — 글자·아이콘·점 */
  --acid-press: #7ce600;    /* --acid 를 누른 상태 */
  --acid-wash: #eaffcb;     /* 형광 한 점을 받쳐주는 언더레이 (면 전용) */
  --on-acid: #14140f;       /* 형광 '위에' 올라가는 글자. 테마와 무관하게 항상 어둡다 */

  /* ── 흰 종이 (기본) ───────────────────── */
  --bg: #ffffff;
  --surface: #fafaf7;       /* 카드 면. 흰 바탕 위에서 아주 살짝 뜬다 */
  --surface-2: #f5f4ef;     /* 인풋 안쪽, 비활성 면 */
  --line: #e8e7e0;          /* 기본 구분선 */
  --line-strong: #d9d7cc;   /* 인풋 테두리처럼 형태를 잡아야 하는 선 */
  --ink: #1a1a17;           /* 따뜻한 먹색 (차가운 #000 금지) — 17.4:1 */
  --ink-soft: #55544c;      /* 본문 보조 — 7.6:1 */
  --ink-faint: #73726a;     /* 메타·캡션 — 4.8:1 (이보다 옅게 내리지 않는다) */

  /* ── 파스텔 종이 (§2 — 면 전용, 채도 낮게) ── */
  --paper-lime:  #f2ffdd;   /* 기본. 형광과 같은 계열이라 제일 자연스럽다 */
  --paper-sky:   #e9f3ff;
  --paper-peach: #fff0e6;
  --paper-lilac: #f2edff;
  --paper-sand:  #faf3e0;

  /* ── 의미색 ──────────────────────────── */
  --happy-accident: #b4551f; /* 에러. 빨강이 아니라 따뜻한 테라코타 — 4.9:1 */
  --caution: #8a5a00;        /* 5.9:1 */
  --danger: #b03a2e;         /* 진짜 파괴적 동작에만 — 6.0:1 */

  /* ── 그림자: 검정이 아니라 따뜻한 그림자 ── */
  --shadow-sm: 0 1px 2px rgba(60, 52, 30, 0.05);
  --shadow-md: 0 6px 20px -6px rgba(60, 52, 30, 0.12);
  --shadow-lg: 0 20px 48px -16px rgba(60, 52, 30, 0.16);

  /* ── 형태: 라이트로 오면서 더 둥글게 ──── */
  --r-sm: 10px;   /* 작은 컨트롤·칩 */
  --r-md: 16px;   /* 카드·인풋 */
  --r-lg: 24px;   /* 큰 패널·히어로 블록 */
  --r-pill: 999px;

  /* ── 여백 스케일 ────────────────────── */
  --s1: 4px; --s2: 8px; --s3: 12px; --s4: 16px;
  --s5: 24px; --s6: 32px; --s7: 48px; --s8: 72px; --s9: 112px;
}

/* 다크는 이제 '기본'이 아니라 '대응'이다. 그래도 누락시키지 않는다. */
@media (prefers-color-scheme: dark) {
  :root {
    color-scheme: dark;
    --bg: #121210;          /* 따뜻한 근-검정 (푸른 검정 금지) */
    --surface: #1b1b17;
    --surface-2: #24231d;
    --line: #2e2d26;
    --line-strong: #403e34;
    --ink: #f2f1e9;
    --ink-soft: #a9a79a;
    --ink-faint: #8a8879;
    --acid-deep: #8fff00;   /* 어두운 바탕에선 형광이 곧 글자색 */
    --acid-wash: #23300f;
    /* --on-acid 는 일부러 다시 선언하지 않는다 (아래 표 참고) */
    --paper-lime:  #1c2413;
    --paper-sky:   #141d28;
    --paper-peach: #261a12;
    --paper-lilac: #1e1a2a;
    --paper-sand:  #241f14;
    --happy-accident: #e8834a;
    --caution: #e0a93b;
    --danger: #e06a5c;
    --shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.3);

  }

/* 뷰어 토글이 미디어쿼리를 이겨야 하면 :root[data-theme="dark"] / ["light"] 에 같은 값을 한 번 더 선언한다. */
```

### 뒤집히는 토큰 vs 안 뒤집히는 토큰 (여기서 제일 많이 깨진다)

| 토큰 | 테마 따라 뒤집히나 | 왜 |
| --- | --- | --- |
| `--ink` · `--bg` · `--line` · `--paper-*` | ✅ 뒤집힌다 | 배경 *위에* 놓이는 것들이라 배경을 따라가야 한다 |
| `--acid-deep` | ✅ 뒤집힌다 | 이름은 '진한 초록'에서 왔지만 **실제 역할은 "현재 배경에서 항상 보이는 초록"**이다. 라이트 `#3d6b00` / 다크 `#8fff00`. 브랜드 점·링크에 이걸 쓰면 한 줄로 양쪽이 해결된다 |
| **`--acid`** | ❌ 안 뒤집힌다 | 브랜드 색 자체다. 늘 `#8FFF00` |
| **`--on-acid`** | ❌ **절대 안 뒤집힌다** | 형광 **위에** 올라가는 글자다. 이 글자의 배경은 테마가 아니라 형광이고, `#8FFF00`은 테마와 무관하게 늘 밝다. 그러니 그 위 글자는 늘 어두워야 한다 |

**가장 흔한 실수: Primary 버튼에 `color: var(--ink)`.** 라이트에선 우연히 맞지만(`#1a1a17` → 13.9:1), 다크로 가면 `--ink`가 크림색(`#f2f1e9`)으로 뒤집혀 **형광 위 크림색 = 1.1:1**, 글자가 증발한다. 반드시 `var(--on-acid)`.

### 중립색은 반드시 '따뜻하게'

순수 회색(`#888`)이나 푸른 검정(`#0e1116`)을 쓰면 시스템이 죽는다. 중립색에 **미세한 올리브/모래 기운**을 넣어야 형광 초록이 "튀는 이물질"이 아니라 "그 종이에서 자란 한 점"이 된다. 이게 밥 아저씨 쪽 축을 붙잡는 장치다.

순백 `#ffffff`는 **바탕에만** 쓴다. 카드는 `--surface`(`#fafaf7`)로 아주 살짝 따뜻하게 띄운다. 흰 위의 흰이라 경계가 약한데, 그게 맞다 — 선으로 나누지 말고 **여백으로** 나눈다.

### 의미색

- **성공** = 형광 초록 그 자체 (그 화면의 한 점이 된다)
- **주의** = `--caution` 따뜻한 앰버
- **행복한 사고(에러)** = `--happy-accident` 테라코타. **빨강이 아니다** — 우리는 다그치지 않는다
- **위험** = `--danger`. 진짜 되돌릴 수 없는 것(삭제 등)에만

## 4. 여백 — 산뜻함의 8할

색이 아니라 **여백**이 이 시스템을 산뜻하게 만든다. 밝은 바탕에서는 빽빽함이 다크보다 훨씬 더 크게 티가 난다 (다크는 어둠이 밀도를 감춰준다).

**섹션 리듬**
- 섹션 사이 세로 여백 `--s8`(72px) ~ `--s9`(112px). *"너무 넓은데?" 싶으면 대체로 맞다.*
- 본문 최대 폭 `65ch`. 카드 그리드 최대 폭 `1120px`.
- 좌우 패딩은 모바일 `--s5`(24px), 데스크톱 `--s6`(32px) 이상.

**카드 내부**
- 패딩 `--s5`(24px) 이상. 카드 안쪽이 좁으면 아무리 둥글려도 답답하다.
- 카드 사이 간격 `--s4`~`--s5`. 카드끼리 붙이지 않는다.

**한 화면 한 이야기**
섹션 하나에 제목 하나 + 한 문단 + 그 섹션의 결과물. 두 가지를 말하고 싶으면 섹션을 나눈다. 넣고 싶은 걸 다 넣으면 Tally가 아니라 대시보드가 된다.

## 5. 타이포

**얼굴**
```css
--font-sans: Pretendard, -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo",
             "Segoe UI", "Noto Sans KR", sans-serif;
--font-mono: ui-monospace, "SF Mono", Menlo, monospace;
```
Pretendard를 1순위로 두고 시스템 폰트로 흘린다. 진지하게 붙일 거면 self-host. **Inter / Space Grotesk는 피한다** — 어디서나 보이는 기본값이라 통일감이 아니라 무개성이 된다.

**규칙**
- 본문은 65자 내외 폭. 제목엔 `text-wrap: balance`, 본문엔 `text-wrap: pretty`.
- 한국어는 `word-break: keep-all` (어절 단위로 끊기게).
- 제목 자간 `-0.02 ~ -0.03em`. 밝은 바탕에서 큰 글씨는 자간을 더 조여야 뭉쳐 보인다.
- 본문 행간 `1.7` 이상. 밝은 바탕에서 행간이 좁으면 눈이 미끄러진다.
- 대문자 라벨은 자간 `+0.08em`, 크기 `0.75rem`, `--ink-faint`.
- 숫자가 세로로 정렬되는 곳엔 `font-variant-numeric: tabular-nums`.
- **강조는 굵기(600~800)로 한다. 색으로 하지 않는다** — 형광은 한 점만 써야 하니까.

**히어로 제목은 크게.** 밝은 바탕 + 넉넉한 여백의 조합은 제목이 작으면 그냥 **텅 빈 화면**이 된다. 여백이 넓어질수록 제목도 같이 커져야 균형이 맞는다.

```css
h1 { font-size: clamp(2.25rem, 6vw, 4rem); font-weight: 800; line-height: 1.12; letter-spacing: -0.03em; }
```

**스케일** (rem)
`0.75 · 0.8125 · 0.875 · 1 · 1.125 · 1.375 · 1.75 · 2.25 · 3 · 4`

## 6. 형태 · 모션

- **모서리**: `--r-sm`(작은 컨트롤) / `--r-md`(카드·인풋) / `--r-lg`(큰 패널·히어로). 버튼과 칩은 `--r-pill`. 라이트 테마에서는 다크보다 한 단계 더 둥글게 간다 — 밝은 면은 각이 서면 딱딱해 보인다.
- **테두리**: 검정 1px 대신 `--line`. **가능하면 테두리 없이 `--surface` 면만으로** 카드를 만든다. 선이 적을수록 산뜻하다.
- **그림자**: 따뜻한 그림자. 남발 금지 — 진짜 떠 있어야 할 것(드롭다운·모달·hover된 카드)만. 카드 기본 상태는 `--shadow-sm` 또는 그림자 없음.
- **hover**: 카드는 `translateY(-2px)` + `--shadow-md` 정도. 색을 바꾸지 않는다.
- **모션**: 180–280ms `cubic-bezier(0.4, 0, 0.2, 1)`. 튀는 스프링/바운스 금지(밥 아저씨는 안 튄다). `prefers-reduced-motion: reduce`는 반드시 존중.

## 7. 컴포넌트 규칙

| 컴포넌트 | 규칙 |
| --- | --- |
| **Primary 버튼** | `background: var(--acid)` + `color: var(--on-acid)` + `--r-pill`. **화면에 하나만.** 이게 그 '한 점'이다. ⚠️ `--ink`를 쓰면 다크에서 글자가 사라진다(§3) |
| **Secondary 버튼** | 투명 배경 + `--line-strong` 테두리 + `--ink` 글씨 + `--r-pill`. hover 시 `--surface-2` 배경 |
| **위험 버튼** | 배경 채우지 않는다. `--happy-accident`/`--danger` 글씨 + 옅은 테두리 |
| **카드** | `--surface` 배경 + `--r-md` + 테두리 없음(또는 `--line` 1px). 내부 패딩 `--s5` 이상 |
| **파스텔 블록** | `--paper-*` 배경 + `--r-lg`. 섹션 구분·히어로·통계 블록에 쓴다. 글자는 `--ink` (§2) |
| **인풋** | `--surface-2` 배경, `--line-strong` 테두리, `--r-md`. 포커스 시 `--acid` 링 |
| **에러 배너** | `--paper-peach` 배경 + 좌측 `--happy-accident` 바 + [무슨 일 / 어떻게 하면 됨]. 아이콘으로 겁주지 않는다 |
| **칩 · 라디오 · 체크박스 · 슬라이더** | **형광 금지 (§2 예산).** 선택됨 = `--ink` 배경 + `--bg` 글씨(또는 `--surface-2` 배경 + `--ink` 글씨). `accent-color`도 `--ink-soft`로. 칩이 10개인 화면이면 형광이 10개가 된다 |
| **포커스 링** | `outline: 2px solid var(--acid-deep); outline-offset: 2px` — 밝은 바탕에서는 `--acid`가 안 보인다(1.27:1). 반드시 `--acid-deep` |

### 브랜드 마크 — 새싹을 얹은 캐릭터

**서비스마다 로고를 새로 그리지 않는다.** 워드마크 앞에 붙는 **캐릭터 마크 하나**가 모든 서비스의 공통 얼굴이다. 둥근 오프화이트 몸에 **머리 위 새싹만 형광 초록**이다.

> **이전 규칙(초록 점 하나)은 폐기했다.** 점은 만들 것도 없고 어떤 이름에도 붙는다는 장점이 있었지만, 기억에 남는 게 **색뿐**이라 "형광 초록 쓰는 사이트" 이상이 되질 않았다. 파비콘으로 쓰면 특히 약했다 — 탭에 점 하나는 아무것도 아니다. 캐릭터는 그리는 비용이 들지만 **얼굴이 남는다.**

**두 벌로 관리한다.** 하나로 퉁치면 반드시 한쪽이 깨진다.

| | 쓰는 곳 | 특징 |
| --- | --- | --- |
| **마크** (`mark.svg`) | 헤더, 파비콘, 앱 아이콘 | 머리만. 눈·입·새싹을 크고 단순하게. **16px에서 읽히는 게 유일한 기준** |
| **캐릭터** (`character.svg`) | 소개 페이지, OG 이미지, 카드 | 전신. 팔다리와 표정까지 |

**마크 규칙**
- **형광은 새싹 하나뿐.** 몸은 중립색이다. 마크가 헤더에 늘 떠 있는데 몸까지 형광이면 §2의 예산이 상시로 새어나간다.
- **몸에 진한 외곽선(`--ink` 계열 3~4px)을 반드시 준다.** 오프화이트 몸을 흰 배경에 그냥 놓으면 형태가 사라진다. 밝은 탭바에서 버티는 건 외곽선이지 몸 색이 아니다.
- **작게 줄였을 때 제일 먼저 죽는 건 눈이다.** 그래서 눈을 실제 비율보다 크게 그린다. 16px로 렌더해서 확인하기 전엔 완성이 아니다.
- 배경은 투명. iOS 앱 아이콘(`apple-icon.png`)만 투명을 못 살리므로 `--paper-lime` 타일 위에 얹는다.
- 크기는 워드마크 글자 크기의 1.5배 내외.

**캐릭터 규칙**
- 새싹 외에는 형광을 쓰지 않는다. 소품을 늘리고 싶어도 색은 중립으로.
- 표정은 **차분한 미소** 하나로 고정. 웃기거나 놀란 표정을 만들면 §1의 "다그치지 않는다"와 어긋난다.

**여전히 유효한 것:** 밝은 배경에서 `--acid`는 1.27:1이다(§3). 새싹처럼 **면으로 칠하는 형광**은 진한 외곽선이나 어두운 이웃이 옆에 있을 때만 성립한다. 형광으로 **선을 긋거나 작은 도형을 찍는 건** 여전히 금지 — 그건 `--acid-deep`이다.

### 서명 — made by kyulolong

모든 서비스에 조용히 넣는다. 헤더 우측 끝 또는 페이지 맨 아래.

```html
<span class="credit">made by kyulolong</span>
```
```css
.credit {
  font-family: var(--font-mono);
  font-size: 0.7rem;
  letter-spacing: 0.06em;
  color: var(--ink-faint);
  opacity: 0.7;
  white-space: nowrap;
  transition: opacity 0.2s ease-out;
}
.credit:hover { opacity: 1; }
```

- **중립색으로.** 서명은 자랑이 아니라 **낙관(落款)**이다 — 형광을 쓰지 않는다. 형광은 사용자가 할 일에만.
- 소문자 그대로, 모노스페이스. 대문자로 키우지 않는다.
- 평소엔 흐릿하게, 마우스를 올리면 또렷하게. 찾으면 거기 있고, 안 찾으면 안 보인다.

## 8. 페이지 뼈대 (랜딩·소개 페이지용)

Tally스러운 페이지는 대체로 이 순서다. 순서를 지키면 반은 먹고 들어간다.

1. **얇은 헤더** — 브랜드 마크 + 링크 두세 개. 배경은 `--bg`, 스크롤 시에만 아래 `--line` 1px. 헤더에 버튼을 넣지 않는다(형광이 두 개가 된다).
2. **히어로** — 큰 제목 한 줄 + 한 문단 + **Primary 버튼 하나**. 여기가 형광 한 점이다. 위아래 여백 `--s9`.
3. **결과물** — 목록·그리드·스크린샷. 히어로 다음에 바로 실물이 나와야 한다. 설명이 먼저 나오면 지루하다.
4. **파스텔 섹션 1~2개** — `--paper-*` 배경 블록으로 리듬을 준다. 연속 두 섹션을 같은 틴트로 칠하지 않는다.
5. **푸터** — 링크 + 서명. 조용하게.

**하지 않을 것:** 히어로 배경에 그라데이션 메시, 스크롤 패럴랙스, 자동 재생 캐러셀, 숫자 카운트업 애니메이션. 전부 "열심히 꾸민 티"가 나고, 이 시스템은 그 반대편에 있다.

## 9. 말투 — 가장 중요한 부분

색은 갈아끼울 수 있지만 말투가 곧 그 서비스의 인격이다. 밥 아저씨는 **여기에** 산다.

**원칙**
1. **절대 다그치지 않는다.** 사용자 탓하는 문장 금지.
2. **실수 = 행복한 사고.** 항상 되돌릴 수 있다고 알려준다.
3. **어려운 걸 쉽게 말한다.** 전문용어 대신 사람 말. (사용자는 *알림*을 관리하지, *웹훅 설정*을 관리하지 않는다)
4. **성공은 담백하게.** "참 쉽죠?"는 강력하지만 **서비스당 한 번만** 아껴 쓴다. 남발하면 유치해진다.
5. **차분한 존댓말.** 느낌표 남발 금지. 이모지는 있어도 한두 개.

**Before → After**

| ❌ 이렇게 쓰지 않는다 | ✅ 이렇게 쓴다 |
| --- | --- |
| "잘못된 입력입니다" | "이 형식이면 바로 돼요: 010-1234-5678" |
| "오류: 위치를 잃었습니다. 대본으로 돌아오세요" | "잠깐 놓쳤어요. 편하게 계속 읽으시면 다시 따라갈게요" |
| "모델을 찾을 수 없음 (404)" | "한국어 모델이 아직 없어요. `npm run get-model` 한 번이면 준비 끝이에요" |
| "필수 항목입니다" | "여기만 채우면 시작할 수 있어요" |
| "저장에 실패했습니다" | "저장이 안 됐어요. 방금 쓰신 내용은 그대로 있으니 다시 눌러보세요" |
| "정말 삭제하시겠습니까?" | "지울까요? 이건 되돌릴 수 없어요" |

**핵심 차이:** 나쁜 문구는 *사용자에게 책임을 넘긴다*("돌아오세요"). 좋은 문구는 *서비스가 책임지고 안심시킨다*("제가 다시 따라갈게요").

## 10. 접근성 (형광을 쓰면 특히 중요)

- 본문 대비 **4.5:1**, 큰 글씨(18px+/굵은 14px+) **3:1** 이상. §3 토큰은 전부 이 기준을 넘게 골랐다.
- **`--acid`를 밝은 바탕 위 글자·아이콘·작은 도형으로 쓰지 않는다** (1.27:1). 반드시 `--acid-deep`.
- **`--ink-faint`보다 옅은 글자색을 새로 만들지 않는다.** 밝은 바탕에서 "예쁘게 연한 회색"은 거의 항상 4.5:1 미만이다.
- **색만으로 정보를 전달하지 않는다.** 형광이 하나뿐이라 더더욱 — 모양·라벨·아이콘을 같이 준다.
- 포커스 링은 항상 보이게(`--acid-deep`). 키보드로 전체 조작 가능하게.
- `prefers-reduced-motion` 존중.

- [ ] §3 토큰 블록 복붙했다 (**라이트가 기본**)
- [ ] **브랜드 마크(캐릭터) + `made by kyulolong` 서명**을 넣었다 (§7)
- [ ] **마크를 16px로 렌더해서 눈이 살아있는지 봤다** (§7 — 여기서 대부분 깨진다)
- [ ] **"이 화면의 형광 한 점은 무엇인가?"** — 하나만 정했다
- [ ] **형광을 세어봤다.** 스크린샷을 찍고 초록을 센다. **주인공 1 + 로고 + 상태점 + 포커스링**을 넘으면 실패 — 특히 `accent-color`(라디오/체크박스/슬라이더)를 확인한다
- [ ] **파스텔 틴트를 글자·테두리·버튼에 쓰지 않았다** (§2 — 면 전용)
- [ ] **글로우가 0개다.** 형광에 `box-shadow`/`text-shadow`를 씌운 곳이 없다
- [ ] 중립색이 따뜻한가? (푸른 회색이면 실패)
- [ ] 형광을 밝은 바탕 위 글자로 쓴 곳이 없나? 포커스 링은 `--acid-deep`인가?
- [ ] **여백이 넉넉한가?** 섹션 사이가 72px 이상인가? 카드 패딩이 24px 이상인가? (§4)
- [ ] **히어로 제목이 충분히 큰가?** 여백만 넓고 글씨가 작으면 빈 화면이 된다 (§5)
- [ ] 에러 문구를 '행복한 사고'로 다시 썼나? (사용자 탓 X)
- [ ] 다크/라이트 둘 다 확인했나? (한쪽만 쓸 거면 그건 *선택*이어야지 *누락*이면 안 된다)
- [ ] **남의 디자인을 요청 없이 바꾸지 않았다.** 색을 바꾸랬으면 색만 바꾼다
